## 0. V2가 이루려는 것

**전 직원이 해피콜을 빠짐없이, 같은 품질로 돌려서 환자 만족도를 올리는 것.**

V1은 "한 명의 직원이 오늘 걸 콜을 놓치지 않는가"를 풀었습니다. V2의 기준은 한 단계 위입니다.

| V1의 기준 | V2의 기준 |
|---|---|
| 직원 한 명이 접수실 PC에서 쓴다 | 직원 누구나, 어느 자리에서나 같은 화면을 본다 |
| 오늘 걸 콜을 안다 | 이번 달 전체를 보고, 빠진 날을 찾아낸다 |
| 통화 결과를 남긴다 | 연락이 안 된 환자를 따로 관리해 끝까지 닿는다 |
| 처방 한 건을 관리한다 | 치료가 끝난 뒤 1년까지 환자를 따라간다 |

환자가 느끼는 차이는 이것입니다. 약이 떨어질 때쯤 전화가 오고, 사정이 생겨 약을 못 먹으면 일정이 그에 맞게 밀리고, 가족이 같은 번호를 써도 누구 이야기인지 바로 알고, 다 나은 뒤에도 반년 뒤에 한 번 더 확인 전화가 옵니다.

## 1. 회의 내용이 어디에 반영됐는지

요청하신 대로, 회의에서 나온 항목이 이 기획안 어디에 들어갔는지 먼저 정리합니다.

| # | 회의에서 나온 말 | 반영 위치 | 반영 상태 |
|---|---|---|---|
| 0 | 해피콜 등록 기준을 처방일이 아니라 **약 발송일** 기준으로 | 2장 전체, 9장 데이터 변경 | 그대로 반영 |
| 1-a | 약을 못 먹거나 약을 교체한 경우 일정을 다시 수정 | 3장 일정 수정 | 조정해 반영 (약 교체는 새 처방으로 등록하고 기존 처방은 마감하도록 권함) |
| 1-b | 달력을 보면서 날짜를 다시 저장 | 3장 일정 수정, 4장 달력 | 그대로 반영 |
| 1-c | 한 달 치 달력에서 날짜별 해피콜 명단 확인 | 4장 달력 | 그대로 반영 |
| 2 | 가족 환자를 같은 번호로 등록, 구분에 '가족' 표시 | 5장 가족 환자 | 조정해 반영 (같은 번호 허용, 구분은 '가족'이 아니라 관계로 표시) |
| 3 | 7일분 투약도 반영 | 6장 투약 기간 | 조정해 반영 (7일 버튼 추가, 콜 시점은 확인 필요 항목으로 남김) |
| 4-1 | 통계 기능 | 7장 통계 | 그대로 반영 |
| 4-2 | 한 달간 연락이 안 된 환자 명단을 따로 저장 | 8장 미연결 관리 | 그대로 반영 |
| 5 | 두드러기 완치 후 1년간 6개월마다 재발 확인 콜 | 9장 재발 확인 콜 | 그대로 반영 |

조정해 반영한 세 가지는 각 장에 이유를 적었습니다.

## 2. 기준 변경: 처방일에서 약 발송일로

V1은 처방일에 약을 바로 받는다고 보고 계산했습니다. 실제로는 약을 달여 보내기 때문에 **복용 시작은 발송일**입니다. 이 기준이 틀리면 뒤의 모든 콜 날짜가 함께 틀어집니다.

**바뀌는 규칙**

| 항목 | V1 | V2 |
|---|---|---|
| 소진일 | 처방일 + 투약일수 | **발송일 + 투약일수** |
| 중간 콜 | 처방일 + 투약일수 절반 | **발송일 + 투약일수 절반** |
| 소진 전 콜 | 소진일 3일 전 | 소진일 3일 전 (그대로) |
| 목·일 당김 | 있음 | 그대로 |

**발송일을 모를 때**

수납 시점에 발송일이 정해지지 않는 경우가 있습니다. 그래서 처방에 **"발송 대기"** 상태를 둡니다.

- 발송일 없이도 환자와 처방은 등록됩니다. 이때는 콜이 만들어지지 않습니다.
- 화면 맨 위에 "발송일 입력 필요 N건"이 뜹니다. 여기를 비워두면 그 환자는 해피콜에서 사라지므로, 눈에 띄게 둡니다.
- 발송일을 넣는 순간 콜 두 건(또는 한 건)이 자동으로 생깁니다.

**처방일도 계속 남깁니다.** 진료가 언제 있었고 약이 언제 나갔는지는 나중에 통계와 문의 대응에 쓰입니다.

## 3. 일정 수정

**왜 필요한가**: 환자 사정으로 복용을 늦게 시작하거나, 중간에 약이 바뀌면 남은 콜 날짜가 전부 어긋납니다. 지금은 고칠 방법이 없습니다.

**무엇을 만드는가**

1. **처방 정보 수정.** 발송일과 투약일수를 고칠 수 있습니다. 고치면 **아직 대기 중인 콜만** 다시 계산합니다. 이미 통화한 콜과 마감된 콜은 그대로 둡니다.
2. **콜 하나만 날짜 바꾸기.** 달력에서 날짜를 골라 저장합니다. 목요일과 일요일은 고를 수 없게 표시합니다. 소진일보다 늦은 날짜를 고르면 "약이 떨어진 뒤입니다"라고 경고합니다.
3. **사유를 남깁니다.** 복용 지연, 약 교체, 환자 요청, 기타 중에서 고릅니다. 누가 언제 왜 바꿨는지 이력에 남아, 다른 직원이 이어받을 때 사정을 압니다.

**약 교체는 이렇게 권합니다 (조정 사항)**: 약이 바뀌면 기존 처방을 "약 교체"로 마감하고 새 처방을 등록합니다. 같은 처방의 날짜만 고치면 어떤 약을 얼마나 먹었는지가 기록에서 사라집니다. 재발이나 부작용을 나중에 따질 때 이 기록이 필요합니다.

## 4. 한 달 달력

**무엇을 만드는가**

- 월 단위 달력을 화면에 둡니다. 날짜마다 그날 콜 건수를 작게 표시합니다. 대기, 완료, 지연을 색으로 구분합니다.
- 목요일과 일요일은 흐리게 표시해 콜이 없는 날임을 한눈에 보입니다.
- 날짜를 누르면 그날의 콜 명단이 아래에 뜹니다. 환자 이름, 콜 종류, 상태, 담당 직원이 보이고, 그 자리에서 통화 기록과 부재중 처리를 할 수 있습니다.
- 지난 날짜를 누르면 그날 못 한 콜이 보입니다. 빠진 날을 찾는 것이 이 기능의 핵심입니다.

**오늘 콜 탭은 그대로 둡니다.** 달력은 한 달을 보는 눈이고, 오늘 콜은 오늘 할 일 목록입니다. 둘의 쓰임이 다릅니다.

## 5. 가족 환자

**지금 문제**: 전화번호 하나에 환자 한 명만 등록됩니다. 어머니 번호로 아이 약을 받는 경우를 넣을 수 없습니다.

**무엇을 바꾸는가 (조정 사항)**

- 같은 전화번호로 여러 환자를 등록할 수 있게 합니다. 환자를 구분하는 값은 번호가 아니라 **번호와 이름**입니다.
- 회의에서는 구분에 '가족'이라고 표시하자고 하셨는데, **관계를 그대로 적는 편**을 권합니다. 본인, 모, 부, 조모, 조부, 자녀, 기타 중에서 고릅니다. 전화를 걸 때 "가족"이라는 표시보다 "자녀"라는 표시가 훨씬 도움이 됩니다.
- 등록 창에서 번호를 넣으면 그 번호로 등록된 환자들이 카드로 보입니다. 거기서 "이 환자에 처방 추가"를 누르거나 "가족 새로 등록"을 누릅니다.
- 콜 카드, 전달 문구, 안내 문자에는 항상 환자 이름과 관계가 함께 나옵니다. 같은 번호로 여러 명이 있을 때 누구 이야기인지 틀리지 않게 하려는 것입니다.

**직원 입장에서 달라지는 것**: 전화를 받은 사람이 환자 본인이 아닐 수 있다는 것을 화면이 먼저 알려줍니다. "어머님, 아이 약 다 먹었을 때쯤 확인차 연락드렸어요"가 자연스럽게 나옵니다.

## 6. 투약 기간 7일 추가

- 처방 일수 버튼을 **30일, 15일, 10일, 7일** 네 개로 늘립니다. 직접 입력도 그대로 둡니다.
- 7일분은 15일 이하이므로 중간 콜 없이 소진 전 콜 한 건만 생깁니다.
- **확인이 필요합니다 (조정 사항)**: 소진 3일 전 규칙을 그대로 쓰면 7일분은 발송 나흘째에 전화하게 됩니다. 약을 절반쯤 먹은 시점이라 이르다고 보실 수도 있습니다. 10일 이하 처방은 **소진 2일 전**으로 할지 원장님 판단이 필요합니다. 이 기획안에서는 일단 소진 3일 전으로 두고, 확인 목록에 올려 두었습니다.

## 7. 통계

**왜 필요한가**: 지금은 오늘 할 일만 보입니다. 이번 달에 몇 건을 놓쳤는지, 나아지고 있는지 알 방법이 없습니다.

**무엇을 보여주는가** (월 단위, 월을 바꿔가며 조회)

| 숫자 | 뜻 |
|---|---|
| 콜 대상 | 그달에 예정됐던 콜 건수 |
| 완료 | 실제로 통화한 건수 |
| 연결률 | 완료 ÷ 대상 |
| **약 떨어지기 전 접촉률** | 소진일 전에 통화나 문자로 닿은 처방 비율 |
| 지연 | 예정일을 넘겨 처리한 건수 |
| 미연결 마감 | 부재 3회로 문자 보내고 마감한 건수 |
| 결과 분포 | 호전, 유지, 악화, 판단보류 비율 |
| 내원 연결 | 내원 필요로 표시한 건수와 그중 예약 완료된 건수 |
| 직원별 처리 | 담당 직원별 통화 건수 |

**약 떨어지기 전 접촉률**이 V1 핵심 질문의 운영 지표입니다. 이 숫자 하나로 도구가 제 역할을 하는지 판단할 수 있습니다.

## 8. 연락이 안 되는 환자 관리

**무엇을 만드는가**

- 부재 3회로 마감된 콜을 **"연락 안 됨" 목록**에 모읍니다. 월별로 조회합니다.
- 목록에는 환자 이름과 관계, 번호, 마지막 시도일, 부재 횟수, 안내 문자 발송 여부가 보입니다.
- 목록에서 **재시도 콜 만들기**를 누르면 날짜를 골라 새 콜을 만듭니다. 원장님 지시로 다시 접촉할 때 씁니다.
- 두 번 이상 연락이 안 된 환자는 **"다음 내원 시 확인"** 표시를 붙입니다. 전화로 못 닿아도 환자가 내원했을 때 데스크에서 붙잡을 수 있습니다.

## 9. 두드러기 재발 확인 콜

**무엇을 만드는가**

- 환자 상세에 **"치료 완료"** 표시를 둡니다. 누르면 완료일이 기록되고, **6개월 뒤와 12개월 뒤** 재발 확인 콜 두 건이 자동으로 생깁니다.
- 이 콜은 종류가 다릅니다. 콜 카드와 달력에 **재발 확인**으로 구분해 표시하고, 오늘 콜 목록에서도 구분됩니다.
- 전용 스크립트를 둡니다. 증상이 다시 올라왔는지, 어떤 상황에서 그런지, 필요하면 내원 안내로 이어집니다.
- 재발이 확인되면 그 자리에서 새 처방 등록으로 이어집니다. 그러면 평소의 해피콜 흐름으로 돌아갑니다.
- 12개월 콜까지 끝나면 추적이 종료됩니다.

**두드러기 외 증상에도 켤 수 있게 만듭니다.** 기침이나 다른 증상도 원장님이 필요하다고 판단하면 같은 기능을 쓸 수 있게 합니다.

## 10. 추천 (회의에서 나오지 않았지만 필요한 것)

아래는 제가 추천하는 항목입니다. 회의에서 언급되지 않았지만, 전 직원이 쓰는 도구가 되려면 필요하다고 판단한 것들입니다.

**추천 1. 직원별 로그인과 담당자 자동 기록 (가장 먼저)**
지금은 이메일 하나만 로그인할 수 있고, 담당 직원 이름을 손으로 칩니다. 직원마다 로그인을 만들고, 통화 기록의 담당자를 로그인한 사람으로 자동 기록해야 합니다. 그래야 통계의 직원별 처리 건수가 의미를 가지고, 인수인계 때 누가 무엇을 했는지 분명해집니다.

**추천 2. 동시에 고쳐도 기록이 덮이지 않게 (가장 먼저)**
직원 두 명이 같은 콜을 동시에 처리하면, 나중에 저장한 쪽이 앞사람 기록을 덮습니다. 저장할 때 "이 콜이 아직 대기 상태일 때만 저장"하도록 막아야 합니다.

**추천 3. 환자가 많아져도 콜이 빠지지 않게 (실제 환자 전 필수)**
현재는 환자를 한 번에 1000명까지만 불러옵니다. 그보다 많아지면 오래된 환자의 콜이 목록에서 조용히 사라집니다. 실제 환자를 넣기 전에 반드시 고쳐야 합니다.

**추천 4. 실제 환자 전환 준비 묶음**
환자에게 해피콜과 기록 보관을 알리는 안내 문구, 개인정보 보관 기간과 파기 기준, 삭제 대신 휴지통, 데이터 내보내기 백업입니다. 실제 환자 정보를 넣는 순간부터 이 네 가지는 선택이 아니라 필수입니다.

**추천 5. 휴진일과 공휴일 달력**
달력 기능을 만들 때 함께 넣는 것이 자연스럽습니다. 명절이나 임시 휴진에 콜이 잡히면 그날 명단이 통째로 밀립니다.

**추천 6. 오늘 못 한 콜 마감 알림**
하루가 끝날 때 처리되지 않은 콜을 화면 위에 띄웁니다. 퇴근 전에 한 번 더 붙잡는 장치입니다.

**추천 7. 원장님 읽기 전용 화면**
지금은 악화 환자를 직원이 메신저로 전달합니다. 원장님이 원장실에서 직접 목록만 볼 수 있으면 전달 누락이 줄어듭니다. 쓰기 권한은 주지 않습니다.

**추천 8. 전화번호 변경 이력**
번호가 바뀌면 지금은 덮어쓰기만 됩니다. 이전 번호를 남겨야 "연락이 안 된다"의 원인이 번호 변경인지 구분할 수 있습니다.

**추천 9. 문자 발송 이력**
지금은 문구를 복사해 직원이 보냅니다. 보냈다는 표시는 남지만 언제 어떤 문구를 보냈는지는 남지 않습니다. 재발송이나 분쟁 대응을 위해 이력을 남깁니다.

**추천 10. 직원 사용 안내문 한 장**
새 직원이 왔을 때 읽을 한 장짜리 안내입니다. 등록, 콜 처리, 부재, 악화 전달의 네 가지 흐름만 담습니다. 도구가 아무리 좋아도 쓰는 방법이 사람마다 다르면 품질이 갈립니다.

**추천 11. 자정이 지나면 화면이 스스로 날짜를 바꾸게**
접수실 PC를 켜둔 채 하루가 바뀌면 오늘 콜 목록이 어제 기준으로 남습니다. 화면을 다시 볼 때 날짜를 새로 계산하게 합니다.

## 11. 만드는 순서

한 번에 다 만들지 않습니다. 각 단계가 끝날 때마다 실제로 쓸 수 있는 상태가 되게 자릅니다.

| 단계 | 내용 | 끝났다고 보는 기준 |
|---|---|---|
| **V2.0 기반** | 추천 1·2·3 (직원 로그인, 덮어쓰기 방지, 환자 수 제한 해소) | 직원 두 명이 각자 로그인해 같은 콜을 처리해도 기록이 섞이지 않는다 |
| **V2.1 기준 변경** | 발송일 기준, 발송 대기 상태, 7일분 추가, 가족 환자 등록 | 발송일을 넣는 순간 콜이 생기고, 같은 번호로 가족 두 명이 각각 관리된다 |
| **V2.2 일정과 달력** | 처방 수정, 콜 날짜 변경, 사유 기록, 월 달력과 날짜별 명단, 휴진일 | 달력에서 지난주에 빠진 콜을 찾아 그 자리에서 처리할 수 있다 |
| **V2.3 통계와 미연결** | 월 통계, 연락 안 됨 목록, 재시도 콜, 다음 내원 시 확인 | 지난달 약 떨어지기 전 접촉률과 연락 안 된 환자 명단을 한 화면에서 본다 |
| **V2.4 재발 확인** | 치료 완료 표시, 6개월·12개월 콜, 전용 스크립트 | 치료 완료를 누르면 6개월 뒤 콜이 잡히고, 달력에 재발 확인으로 구분돼 보인다 |
| **실제 환자 전환** | 추천 4 묶음 완료 후 실제 환자 입력 시작 | 안내 문구, 보관 기준, 휴지통, 백업이 모두 준비됐다 |

실제 환자는 **V2.0과 추천 4가 끝난 뒤**에 넣는 것을 권합니다. V2.1 이후 기능은 실제 환자를 쓰면서 이어가도 됩니다.

## 12. 데이터가 어떻게 바뀌는가

| 표 | 바뀌는 것 |
|---|---|
| `patients` | 전화번호 단독 고유값 해제, 이름과 번호 조합으로 구분. 관계(본인·모·부·조모·조부·자녀·기타) 추가. 치료 완료일 추가 |
| `prescriptions` | 발송일 추가, 상태에 "발송 대기" 추가, 마감 사유에 "약 교체" 추가 |
| `calls` | 종류에 재발 확인 6개월·12개월 추가, 일정 변경 사유와 변경자 추가 |
| `call_attempts` | 그대로. 담당자는 로그인 계정으로 자동 기록 |
| 새 표 `staff` 또는 허용 이메일 확장 | 직원 계정과 표시 이름 |
| 새 표 `closed_days` | 휴진일과 공휴일 |
| 새 표 `sms_log` | 보낸 문자 문구와 시각 |

기존 데이터는 예시 환자뿐이므로, 발송일은 기존 처방일과 같게 채우고 시작합니다.

## 13. 확인이 필요한 것

구현 계획을 쓰기 전에 원장님과 직원의 답이 필요한 항목입니다.

1. 7일분과 10일분의 소진 전 콜을 소진 3일 전으로 둘지, 2일 전으로 당길지.
2. 발송일이 정해지지 않은 처방을 며칠까지 "발송 대기"로 두고, 그 뒤에는 어떻게 할지.
3. 재발 확인 콜을 두드러기에만 켤지, 기침 등 다른 증상에도 켤지.
4. 연락이 두 번 이상 안 된 환자에게 문자 외에 다른 방법을 쓸지.
5. 직원 계정을 몇 개 만들지, 누구에게 줄지.
6. 통계를 누가 언제 보는지. 월말 한 번인지, 매주인지.
7. 환자에게 해피콜과 기록 보관을 어떻게 알릴지.

## 14. V2에서도 하지 않는 것

- 한의사랑 자동 연동. 고객센터 답을 받은 뒤 별도로 판단합니다.
- AI 음성봇.
- 환자용 화면.
